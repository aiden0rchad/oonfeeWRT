# oonfeeWRT v0.1.7

v0.1.7 introduces the **Precision interface**: a slimmer controller shell,
clearer navigation groups, compact device and topology presentation, and a
consistent orbit identity. It refines the capabilities delivered in v0.1.6;
it does not introduce new router operations, measurement sources, or a database
migration.

Prepared September 12, 2026. The completed `v0.1.7` tag workflow and GitHub
release establish publication. Verify standalone archives with `SHA256SUMS`
and verify the container's keyless signature, provenance, SBOM, and immutable
digest. Source notes or a tag alone do not establish that artifacts are ready.

## Precision presentation

- A 56-pixel icon rail expands into a 184-pixel labeled sidebar. The existing
  account-and-controller-scoped browser preference is preserved.
- **Workspace** groups Dashboard, Devices, Client Devices, Topology, Radios,
  Policy Engine, and adoption. **Insights** groups Statistics, Reports, and
  Alerts. Settings, Accounts, and Logs remain at the bottom.
- A compact account footer shows the signed-in name and role and opens
  **My account**. Labels and tooltips remain available when the rail is
  collapsed; sign-out and theme controls remain available in the header.
- Restrained dark/light surfaces, thinner borders, slimmer desktop controls,
  less rounded cards, and reduced decorative weight give data more room.
  Smaller visual controls do not remove keyboard focus, accessible names,
  mobile/coarse-pointer touch targets, or safety information.
- Device cards and topology nodes use quieter presentation. Topology layout
  edits still affect only the drawing saved in the browser, scoped by account,
  controller origin, and Current/History mode. They do not infer links or
  change device configuration.
- The Dashboard fleet summary uses one shared strip with inset dividers,
  clearer labels, and right-aligned values. It reflows for narrow screens
  without clipping observation notes. These remain the existing fleet counts
  and measurements, not new telemetry or inferred health.

## Firmware and Integrations inside Settings

Settings now contains **Network**, **Firmware**, **Integrations**,
permission-gated **Diagnostics**, and owner-only **Backup & Restore**.
Accounts remains its own workspace.

The canonical section links are:

- `/settings?section=firmware`
- `/settings?section=integrations`

Existing `/firmware` and `/integrations` bookmarks continue to open the
corresponding Settings section. Section changes update the URL and browser
history. Keyboard tab navigation keeps focus in the tablist; unauthorized
section fallbacks replace the invalid history entry rather than trapping Back.

Moving a screen changes navigation, not authority. Opening Firmware reads
stored inventory; catalogue checks remain explicit Admin/Owner actions.
Opening Integrations reads saved, redacted connection settings. Saving an
AdGuard connection still requires an Owner and recent reauthentication and
does not contact the service. AdGuard and WireGuard checks remain explicit,
permission-gated reads. No DNS/VPN service is configured by this release.

## Reports and responsive correctness

Reports now binds a loaded result to both its selected period and refresh
revision before rendering it or enabling CSV export. Selecting a different
period cannot present or export the prior selection as the new one while its
replacement is pending. Late completed requests remain rejected.

CSV continues to export the selected report's exact sample-weighted values,
UTC boundaries, current/prior coverage, and available observations. Display
rounding does not round exported values. Missing intervals remain unknown,
not proof of zero traffic, downtime, or continuous uptime.

Navigation, responsive layout, embedded Settings permissions, deep links,
browser history, account footer access, report selection, and actual CSV
downloads have regression coverage. These changes do not add collection
traffic or contact routers merely to populate a screen.

## Orbit project identity

The chosen orbit mark is used in the application shell, sign-in/setup,
README, documentation, favicon, and installed-app icons. It adapts Lucide's
**Orbit** geometry with a 1.5-unit stroke and project colors.

This is a **nonexclusive icon-based mark**, not a claim of original or
exclusive artwork. Lucide's ISC notice and pinned source provenance are
retained in `third_party/lucide-orbit/`, `NOTICE`, and the generated
`THIRD_PARTY_LICENSES` bundled with releases. SVGs retain the notice; PNG icons
also retain it in their metadata.

The 192- and 512-pixel installed-app icons are generated locally from the
checked-in SVG master. The mark stays within the maskable icon safe zone.
ImageMagick is needed only to regenerate those assets, not to build or run the
controller. There is no new runtime dependency or remote artwork service.

## Upgrade and rollback

**v0.1.6 → v0.1.7 stays on database schema 25.** There is no new schema
migration, re-adoption requirement, automatic helper installation, or router
write introduced by the Precision interface. Keep a verified backup and a
matching database/keyring/runtime-passphrase recovery unit before upgrading,
then deploy the verified binary or pinned container and refresh the browser.

Returning to v0.1.6 does not cross a database schema boundary. Preserve the
pre-upgrade v0.1.6 binary/image and recovery unit; never run two controllers
against the same data directory. Configuration changes made while either
version is running are not undone merely by replacing its executable.

Upgrades from v0.1.5 still run the existing ordered **23 → 24 → 25**
migrations for persistent alerts and encrypted integration settings. Earlier
supported stores run the existing prior migrations first. v0.1.5 cannot open
schema 24/25; rolling back to it requires the untouched matching schema-23
recovery unit, not just an image-tag or binary change.

Ordinary upgrades preserve existing restored-controller write suppression.
A portable restore still pauses external alert delivery and cancels queued
notifications; an Owner must review the destination and explicitly re-enable
delivery. It does not replay cancelled notifications or resume router writes
just to verify an upgrade.

Follow `docs/installation/upgrades.md` and the bundled `INSTALL.md` for
verified installation, backups, recovery, and rollback procedures.

## Validation and unchanged limits

Release gates cover Go tests, race detection, vet, module and vulnerability
checks, UI unit/browser tests, production and isolated-demo builds, bundle
budget, screenshot/documentation checks, secret scans, reproducible archives,
container backup/restore, signed multi-platform image publication, and release
asset checksums. Use the completed workflow for the exact released commit as
the final validation record; source preparation is not a passing CI claim.

Firmware remains **catalogue-only**: no controller-managed image download,
staging, flashing, or post-flash recovery engine is provided. The optional
read-only rpcd helper remains experimental manual source, without a prebuilt
SDK-validated router package. SNMP, Web Push, full localization, DPI/application
traffic history, VM inventory, and public demo hosting remain outside this
release. No new physical-router validation or complete feature-parity claim
is made.
